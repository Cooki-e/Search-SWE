# Data attribution and license

The schema metadata and sampled rows are adapted from Spider 1.0, by Tao Yu and the Spider collaborators at Yale/LILY. The official dataset is distributed under [Creative Commons Attribution-ShareAlike 4.0 International](https://creativecommons.org/licenses/by-sa/4.0/), as stated on the [Spider dataset page](https://yale-lily.github.io/spider). These adapted data use the same license, covering `data/` and `tests/data/`. Version 0.5.0 contains five unchanged original Spider questions and 35 questions authored for this task by Bingyu. The authored questions are not Spider's original annotations. All selected questions and their derived table/join labels are distributed under CC BY-SA 4.0.

Reference: Tao Yu et al., *Spider: A Large-Scale Human-Labeled Dataset for Complex and Cross-Domain Semantic Parsing and Text-to-SQL Task*, EMNLP 2018, [paper](https://arxiv.org/abs/1809.08887).

Adaptation by Bingyu: uniform schema/sample extraction; opaque identifiers; author-created questions; derived and reviewed table/column join labels; new validation/evaluation splits. Version 0.3.1 reconciled table descriptions in the released `test_tables.json` against `tables.json`, matched by database ID and original table name after checking schema identity: 16 misassigned descriptions and two spacing differences in `scholar` and `formula_1`. Version 0.4.0 also restores 200 missing primary-key membership flags across 161 tables from the original SQLite declarations, independently of question selection. Table/column identities, samples and public relationships are unchanged. No endorsement by the original authors is implied. This data license is distinct from the license of Spider's evaluation code; the code license is not substituted for the data license.

Version 0.5.0 retains the corrected 0.4.0 catalog byte-for-byte and changes question selection and splits. Selection is conditioned on an archived retrieval implementation's observed performance; identical table-and-join structures do not cross splits, while database families may overlap.
